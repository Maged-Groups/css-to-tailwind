🚀 Your first Tailwind CSS 4 project

From Plain HTML + CSS
to Tailwind CSS 4

In this project, you'll convert a Portfolio page built with plain HTML and CSS into the same page built entirely with Tailwind CSS 4. The conversion only touches styling — the structure and data stay exactly as they are.

HTML CSS → Tailwind 4 Dark Mode Responsive JS (later)

🎯

Goal

Convert the whole page to utilities and delete styles.css

⏱️

Duration

2 – 3 hours of actual work

📦

Deliverable

index.html + structure ready for JavaScript

💡 Read this first

You're not converting some throwaway design — you're building a portfolio that will actually be used. After you learn JavaScript, you'll come back to this file and add just 10 lines to make the page alive (dark mode works with a click, and filters work with a click). That is the difference between an exercise and a real project.

1

Setup

Add Tailwind 4 via CDN to your index.html.

Open <head> and add the following before styles.css:

index.html
<!-- Tailwind 4 Browser Build -->
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4"></script>

<!-- Tailwind 4 config (we'll fill this in later) -->
<style type="text/tailwindcss">
  /* We'll add @theme here later */
</style>

⚠️ Don't delete styles.css yet

You'll need it as a reference during the conversion. Only at the very end will you delete it.

2

Converting :root to @theme

This is the first real power of Tailwind 4 — variables automatically become utilities.

❌ Before (styles.css)

styles.css
:root {
  --color-primary: #6366f1;
  --color-bg: #f8fafc;
  --radius-lg: 16px;
  --font-sans: "Inter", sans-serif;
}

✅ After (index.html)

index.html
<style type="text/tailwindcss">
  @theme {
    --color-primary: #6366f1;
    --color-bg: #f8fafc;
    --radius-lg: 16px;
    --font-sans: "Inter", sans-serif;
  }
</style>

🎯 What just happened?

Once you write --color-primary inside @theme, it becomes available as a utility:

  • bg-primary — background
  • text-primary — text color
  • border-primary — border
  • rounded-lg — border radius
  • font-sans — font family
3

Enabling Dark Mode

The single most important line in the whole project. If you forget it, dark: will never work.

⚠️ A critical difference from Tailwind 3

In Tailwind 4, dark mode defaults to the system preference. To enable it via class="dark" on <html>, you need an explicit line.

index.html — inside the style tag
@custom-variant dark (&:where(.dark, .dark *));

How does it work?

<html class="dark">

🌙 Dark mode active — every dark: utility works

<html>

☀️ Light mode — dark: does nothing

Example — converting the theme toggle:

❌ Before (CSS)

styles.css
.theme-icon--sun { display: none; }
.dark .theme-icon--sun { display: inline; }
.dark .theme-icon--moon { display: none; }

✅ After (Tailwind)

index.html
<span class="dark:hidden">🌙</span>
<span class="hidden dark:inline">☀️</span>

Notice: the icon switches without any JavaScript — pure CSS. When you learn JS, all you'll do is toggle a class on <html>, and the icon will switch automatically.

🔌

JavaScript Phase — Later

This phase is not to be completed now. But we've added every "socket" so it's ready.

💡 Why plan for this now?

Because we're teaching you a professional architectural principle: separate presentation (HTML+CSS) from behavior (JS). Today you build the full interface and leave "sockets" — tomorrow you wire the electricity in 10 lines.

🎨 Feature 1: Theme toggle

All you need is to toggle a class on <html>. Everything else (icon and color changes) is handled by CSS automatically.

script.js
const toggle = document.getElementById('theme-toggle');

toggle.addEventListener('click', () => {
  document.documentElement.classList.toggle('dark');
});

✅ 3 lines only — that's all it takes. All dark-mode styling already exists via dark:.

🔍 Feature 2: Filtering projects

When they learn JS, they'll add this code that reads data-filter from the buttons and data-category from the cards.

script.js
const filterButtons = document.querySelectorAll('.filter-btn');
const projectCards  = document.querySelectorAll('.project-card');

filterButtons.forEach((btn) => {
  btn.addEventListener('click', () => {
    // 1. Update the active state
    filterButtons.forEach((b) => b.classList.remove('bg-primary', 'text-white', 'border-primary'));
    btn.classList.add('bg-primary', 'text-white', 'border-primary');

    // 2. Filter the cards
    const filter = btn.dataset.filter;
    projectCards.forEach((card) => {
      const cats = card.dataset.category.split(' ');
      card.hidden = filter !== 'all' && !cats.includes(filter);
    });
  });
});

⚠️ Why card.hidden and not display:none?

Because hidden is a standard HTML attribute that fully removes the element from the Flex layout without breaking the flow. You'll discuss this in more depth when you reach that phase.

Common Mistakes & Fixes

It happens to everyone. Let's walk through them quickly.

❌ Dark mode doesn't work even though I added dark: ▾

Two possibilities:

  1. You forgot the line @custom-variant dark (...) inside <style type="text/tailwindcss">.
  2. You didn't add class="dark" on <html> or didn't test toggling it.
❌ Tailwind classes don't work (page has no styling) ▾

Verify:

  • The CDN script exists before the <style> tag.
  • The style script is of type text/tailwindcss, not text/css.
  • You're connected to the internet (the CDN loads remotely).
❌ bg-primary doesn't work ▾

You must have added this in @theme: 

--color-primary: #6366f1;

In Tailwind 4, if you haven't defined the variable, it won't auto-generate a utility.

❌ Page overflows horizontally on mobile ▾

Look for an element with:

  • w-[680px] fixed width or a large min-w-*.
  • An image without max-w-full.
  • Cards with fixed desktop widths (for example w-[calc((100%-3rem)/3)]) and no w-full / sm: / lg: breakpoints.
